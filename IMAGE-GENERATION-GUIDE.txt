1. WHAT WAS BUILT
--------------------------------------------------------------------------------
All 20 images on the website were generated LOCALLY on this machine's NVIDIA
RTX 2070 SUPER (8 GB) using Stable Diffusion XL 1.0 (open-source, Apache-2.0,
by Stability AI) run through the HuggingFace "diffusers" Python library.
Prompts were engineered from IMAGE-BRIEFS.txt (compressed to fit SDXL's
77-token text-encoder limit), each image uses a FIXED RANDOM SEED so results
are reproducible, and outputs are WebP files in public/images/ wired into the
site through the MediaFrame component and the Applications domain grid.

  torch / torchvision 2.6.0+cu124   CUDA build from download.pytorch.org/whl/cu124
  diffusers 0.40.0                  runs the SDXL pipeline
  transformers                      CLIP text encoders used by SDXL
  accelerate                        CPU-offload support (VRAM saver)
  safetensors                       fast safe weight loading

Why SDXL base: best open-source quality that FITS IN 8 GB VRAM.
(FLUX.1 needs 12-24 GB; SDXL-Turbo is faster but flatter; SD 1.5 is worse.)

4. EVERY STEP TAKEN, IN ORDER (reproduce on any machine)
--------------------------------------------------------------------------------
STEP 0 - Check GPU
  nvidia-smi          (need an NVIDIA card; 6 GB+ VRAM recommended)

STEP 1 - Create isolated Python environment (keeps system clean)
  python -m venv "%TEMP%\opencode\imgen\venv"
  On this PC that resolved to:
    C:\Users\AIC_PECF WS1\AppData\Local\Temp\opencode\imgen\venv

STEP 2 - Install CUDA PyTorch (biggest download, ~2.4 GB)
  <venv>\Scripts\pip.exe install torch torchvision --index-url https://download.pytorch.org/whl/cu124
  Verify:
  <venv>\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
  must print True

STEP 3 - Install diffusion libraries (~100 MB)
  <venv>\Scripts\pip.exe install diffusers transformers accelerate safetensors sentencepiece protobuf

STEP 4 - What the script (scripts/generate-images.py) does internally:
  a) Defines NEG (negative prompt), WAFEE (robot identity block),
     STYLE (grading suffix), and S() which composes scene + WAFEE + STYLE.
  b) SLOTS table = one row per image:
        (filename, width, height, seed, prompt)
     Sizes chosen per aspect ratio, multiples of 16 px:
        21:9 plates -> 1680x720      16:9 frames -> 1280x720
        4:3 tiles   -> 1152x864
     Seeds: img-01..06 use 101-106, plates 09..13 use 110-114,
            tiles d1..d9 use 201-209.
  c) Loads SDXL fp16 from the HuggingFace cache.
  d) VRAM GUARD (critical on shared machines):
        free_gb = torch.cuda.mem_get_info()
        mode = "gpu" if free >= 7 GB else "offload"
     offload = pipeline.enable_model_cpu_offload()
  e) Memory extras: pipe.vae.enable_slicing() and pipe.vae.enable_tiling().
  f) Token guard: prints token count per prompt; CLIP truncates above 77,
     flagged as TOO LONG in the log (all current prompts are within limit).
  g) Generation settings: steps=30, guidance_scale=6.0, fixed seed per slot.
  h) On CUDA OOM mid-run: frees memory, reloads pipeline in offload mode,
     retries that slot automatically.
  i) Saves WebP quality 82 into public/images/, logs size + time.
  j) SKIPS files that already exist, so it is safe to interrupt/resume.

STEP 5 - Run it (PowerShell):
  $py = "C:\Users\AIC_PECF WS1\AppData\Local\Temp\opencode\imgen\venv\Scripts\python.exe"
  $env:HF_HUB_DISABLE_SYMLINKS_WARNING="1"
  $env:PYTORCH_CUDA_ALLOC_CONF="expandable_segments:True"
  & $py -u scripts\generate-images.py *> gen_log.txt
  Optional filter argument regenerates only matching slots:
  & $py -u scripts\generate-images.py img-04
  First run downloads the model (~10 min); later runs start in seconds.

STEP 6 - Site integration (already done; reference for future slots):
  media-frame.tsx: MediaFrame / MediaVisual / Lightbox accept src?: string.
  When present they render <Image fill object-cover> under the HUD overlay
  (corner brackets, CR code chip, Concept badge, label bar) and hide the
  Awaiting Imagery placeholder. When absent the placeholder still shows.
  Call sites pass e.g. src="/images/img-03-lab.webp".
  Applications tiles: DOMAIN_IMAGES maps domain ids to files; DomainGrid
  renders image + hover zoom + gradient scrim behind the brackets.

STEP 7 - Verify
  npm run build, then check routes on localhost:3000.

5. PROBLEMS HIT DURING THE BUILD AND HOW THEY WERE SOLVED
--------------------------------------------------------------------------------
PROBLEM 1 - Process died silently with no output at all.
  CAUSE : SOLIDWORKS / Blender / Metashape were consuming VRAM concurrently;
          SDXL needed about 7 GB but less was free. stdout was also piped and
          buffered so crash output vanished before display.
  FIX   : VRAM guard selecting enable_model_cpu_offload(); unbuffered (-u)
          logging redirected to a FILE via PowerShell (*> gen_log.txt);
          automatic OOM retry logic; PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
  LESSON: close VRAM-heavy apps OR rely on offload mode (slower but safe).

PROBLEM 2 - Prompts silently truncated by CLIP.
  CAUSE : SDXL text encoders cap at 77 tokens; first drafts were ~165 tokens
          so most scene detail plus the STYLE suffix never reached the model.
  FIX   : compressed WAFEE identity to one short block and trimmed scenes;
          script now prints real token counts per prompt for control.

PROBLEM 3 - diffusers API change.
  CAUSE : pipe.enable_vae_slicing() no longer exists in diffusers 0.40.
  FIX   : use pipe.vae.enable_slicing() and pipe.vae.enable_tiling().

PROBLEM 4 - PowerShell mangled inline node/python one-liners (escaping).
  FIX   : write helper code to .py/.mjs FILES and execute those instead of
          passing complex strings through shell -e flags.

PROBLEM 5 - One file survived cleanup due to a bad wildcard path, so the
  script skipped it (skip-if-exists behavior). Deleted it explicitly and reran.

7. HOW TO REUSE / CHANGE THINGS (cheat sheet)
--------------------------------------------------------------------------------
REGENERATE ONE IMAGE WITH A NEW LOOK:
  1. Open scripts/generate-images.py, find its SLOTS row.
  2. Change the prompt text and/or bump the SEED by any amount.
  3. Delete public/images/<file>.webp (script skips existing files).
  4. Run: & $py -u scripts\generate-images.py <part-of-filename>
  5. Refresh the site; next/image serves the new asset automatically.

ADD A BRAND NEW IMAGE SLOT:
  1. Add row to SLOTS (filename, w, h, unique seed, prompt).
  2. Run script with filter; file lands in public/images/.
  3. Render <MediaFrame code="IMG-XX" label="..." ratio="..." src="/images/<file>.webp" />
     anywhere; lightbox and HUD overlay come free.

TUNING KNOBS (inside the script):
  num_inference_steps  30 (20 = faster draft, 40+ = slightly finer detail)
  guidance_scale        6 (higher = literal to prompt, lower = more creative)
  WebP quality         82 (raise to 90 for masters, keep under ~180 KB/file)
  negative prompt NEG  add anything you keep seeing and dislike

RUN ON ANOTHER MACHINE FROM SCRATCH:
  Repeat steps 0-5 above. Only prerequisites: NVIDIA GPU + driver,
  Python 3.10+. Everything else installs locally into the venv; the model
  cache (~7 GB) can be copied between machines to skip the download:
  copy %USERPROFILE%\.cache\huggingface\hub\models--stabilityai--stable-diffusion-xl-base-1.0

NO-GPU FALLBACK (free hosted generator running open-source FLUX.1-schnell):
  https://image.pollinations.ai/prompt/<url-encoded-prompt>?width=1680&height=720&seed=101&nologo=true&model=flux
  Same prompts work; save response into public/images/.

CAUTION:
  The venv lives under TEMP and Windows may clear it eventually. Recreate via
  steps 1-3. The model cache in %USERPROFILE%\.cache survives independently.
  scripts/generate-images.py in the repo is the canonical copy - keep it in
  sync with any edits made to the Temp working copy.
