CENNZO ROBOTIX — PREMIUM LIGHT-THEME WEBSITE & MOTION DESIGN SPEC
Instruction document for OpenCode

OBJECTIVE
Build a premium, futuristic, engineering-first website for Cennzo Robotix using a LIGHT visual system. The website should feel like a serious advanced robotics company—not a generic SaaS landing page.

Core visual references:
- Apple-level restraint and typography
- Space/engineering-grade precision
- Premium robotics/product presentation
- Cinematic Awwwards-style motion
- Strong usability and accessibility

The experience must feel intelligent, precise, technical, clean and expensive.

============================================================
1. TECHNOLOGY / ARCHITECTURE
============================================================

Preferred stack:
- React
- Vite
- TypeScript
- Tailwind CSS
- GSAP
- GSAP ScrollTrigger
- Motion / Framer Motion for UI interactions
- Lenis for smooth scrolling
- Three.js / React Three Fiber for 3D where useful
- Drei where useful
- CSS transforms, masks, gradients and backdrop effects
- WebGL shaders only where they provide real value

Architecture principles:
- Componentize every major section.
- Keep animation logic separate from content and layout where practical.
- Use reusable animation utilities.
- Use CSS variables/design tokens for colors, spacing, radii and motion.
- Respect prefers-reduced-motion.
- Do not make the site dependent on heavy animation for basic usability.
- Avoid unnecessary libraries.
- Keep the initial page load fast.
- Lazy-load 3D, videos and heavy assets.
- Do not create animation merely because the technology allows it.

============================================================
2. LIGHT-THEME VISUAL SYSTEM
============================================================

DO NOT use a basic white-background + blue-button template.

Use a sophisticated near-white foundation.

Suggested palette:

Primary background:
- #F7F8FA — main page background

Secondary surface:
- #FFFFFF — cards and important content

Soft technical surface:
- #EEF1F4 — section separation / technical panels

Primary text:
- #111318 — headings and high-priority content

Secondary text:
- #4B5563 — body copy

Muted text:
- #7A8491 — supporting metadata

Primary brand accent:
- #155EEF — controlled electric blue

Deep technical accent:
- #0B1220 — dark navy/ink

Optional secondary accent:
- #00A8A8 — restrained cyan/teal for sensors, telemetry or AI states

Alert/status:
- #D92D20 — only for warnings/errors

Success:
- #039855

Rules:
- Never use the full accent color everywhere.
- Accent should communicate interaction, technology or important state.
- Most text should remain dark neutral.
- Avoid excessive blue gradients.
- Avoid rainbow gradients.
- Avoid putting light-gray text on white.
- Avoid pure #000000 unless required.
- Maintain strong WCAG contrast.
- Use dark technical sections selectively to create visual rhythm.

Recommended visual ratio:
- 65–75% near-white / white
- 15–20% soft gray surfaces
- 5–10% dark technical areas
- 2–5% accent color

============================================================
3. COLOR & CONTRAST PLACEMENT
============================================================

Use contrast as a storytelling tool.

Hero:
- Light background.
- Dark headline.
- Robot/product as dominant visual.
- Small electric-blue accents.
- Very subtle grid/noise.

Technology sections:
- Alternate between white and #F7F8FA.
- Use thin borders rather than heavy shadows.
- Technical diagrams can use navy + blue + cyan.

Dark sections:
Use sparingly for:
- AI/intelligence
- telemetry
- final vision statement
- cinematic product reveal

Dark section:
- Background #0B1220
- Primary text #FFFFFF
- Secondary text approximately #CBD5E1
- Blue/cyan only for data and interactive states

Cards:
- White surface
- 1px subtle neutral border
- Very soft shadow
- Slight elevation on hover
- Never use huge drop shadows

Buttons:
Primary:
- Dark navy/ink background
- White text
- Blue/cyan interaction state

Secondary:
- Transparent/white background
- Dark text
- Neutral border

Avoid giant pill-shaped buttons unless the design clearly benefits from them.

============================================================
4. TYPOGRAPHY
============================================================

Use a premium modern sans-serif.

Recommended:
- Inter
- Geist
- Manrope
- IBM Plex Sans for technical areas if appropriate

Typography hierarchy:
- Massive hero heading
- Strong section headings
- Medium technical labels
- Comfortable body text
- Small uppercase metadata labels

Hero headline should be short and powerful.

Use:
- tight heading line-height
- moderate body line-height
- generous whitespace
- controlled letter spacing

Do not make every heading uppercase.

Use uppercase primarily for:
- section labels
- technical metadata
- navigation microcopy
- status indicators

============================================================
5. LAYOUT / SPACING
============================================================

Use a strong grid.

Desktop:
- max content width around 1200–1440px
- generous horizontal margins
- 12-column grid where appropriate

Mobile:
- preserve hierarchy
- reduce motion complexity
- never force horizontal scrolling accidentally
- horizontal storytelling sections should remain intentional and usable

Use generous whitespace.

Do not fill every empty area.

Premium design needs breathing room.

============================================================
6. NAVIGATION
============================================================

Navigation should be minimal.

Desktop:
- Cennzo logo
- Technology
- Products
- Applications
- About
- Contact
- one primary CTA

Behavior:
- Initially transparent/clean over hero if readable.
- On scroll, transition into a compact glass/white navigation surface.
- Subtle backdrop blur.
- Small height reduction during scroll.
- Smooth transition.
- Avoid a huge sticky navbar.

Mobile:
- clean menu interaction
- animated menu open/close
- accessible keyboard/focus behavior

============================================================
7. HERO — CINEMATIC BUT LIGHT
============================================================

Hero should immediately establish Cennzo as an advanced robotics company.

Composition:
- large headline on one side
- humanoid/robot visual on the other or centered depending on asset quality
- strong whitespace
- small technical metadata
- primary CTA
- secondary CTA

Animation sequence:
1. Page loads.
2. Background appears softly.
3. Logo/nav settles.
4. Robot fades/reveals with slight upward movement.
5. Headline reveals by word/line.
6. Supporting text appears.
7. CTA appears last.
8. Very subtle ambient movement continues.

Robot:
- If a high-quality 3D model exists, use React Three Fiber.
- Otherwise use optimized image/video.
- Add extremely subtle idle/breathing/servo-like movement.
- Do not overanimate the robot.

Cursor interaction:
- Very subtle parallax.
- Lighting/highlight may follow cursor.
- Background particles/grid respond minimally.

============================================================
8. HORIZONTAL SCROLL STORYTELLING
============================================================

Use horizontal scrolling for one or two major storytelling sections—not the entire site.

Preferred pattern:
Vertical scroll input
→ section pins
→ content travels horizontally
→ section completes
→ normal vertical scroll resumes.

Example technology journey:
PERCEPTION
→ INTELLIGENCE
→ MOBILITY
→ AUTONOMY
→ APPLICATIONS

Implementation:
- GSAP ScrollTrigger pinning
- horizontal translation controlled by scroll progress
- calculate width dynamically
- avoid hard-coded screen assumptions
- ensure mobile fallback

Do NOT create an infinite horizontal carousel.

The horizontal section should have a clear beginning and end.

============================================================
9. PINNED ROBOT / PRODUCT STORY
============================================================

Create a premium scroll-controlled product showcase.

Concept:
As the user scrolls:
- robot rotates
- camera changes
- technical callouts appear
- components highlight
- data panels transition

Potential sequence:
0% — FRONT
25% — PERCEPTION
50% — ACTUATION
75% — INTELLIGENCE
100% — FULL SYSTEM

If a 3D model is available:
- rotate the model based on scroll progress
- animate camera position
- animate lights
- reveal hotspots

If no 3D model:
- use carefully prepared image sequence/video instead.

Do not fake a 3D effect with excessive image scaling.

============================================================
10. INTERACTIVE COMPONENTS
============================================================

Cards:
- slight lift
- slight scale
- border/highlight response
- optional image reveal
- subtle gradient/light movement

Do not use exaggerated 3D card tilting everywhere.

Magnetic buttons:
- attraction should be subtle, approximately 5–15px
- spring back naturally
- disable or simplify on touch devices

Cursor:
- optional custom cursor on desktop only
- never hide the system cursor if accessibility/usability is harmed
- cursor effects should be subtle

Hover:
- use hover to reveal information
- never require hover to access essential content

============================================================
11. SCROLL-VELOCITY ANIMATION
============================================================

Use scroll velocity selectively.

When user scrolls quickly:
- subtle text/image skew
- slight velocity-based parallax
- controlled motion blur if technically safe

When scrolling stops:
- elements settle smoothly.

Do not create nausea-inducing distortion.

The animation should communicate momentum, not chaos.

============================================================
12. TEXT ANIMATION
============================================================

Use kinetic typography carefully.

Techniques:
- word-by-word reveal
- line reveal
- character reveal for short headlines
- masked text reveal
- slight vertical movement
- opacity + transform

Avoid:
- every paragraph animating letter by letter
- excessive bouncing
- typewriter effect for normal marketing copy

Hero and major statements can use stronger animation.
Body copy should remain readable and stable.

============================================================
13. CLIP-PATH / MASK REVEALS
============================================================

Use:
- image mask reveals
- rectangular technical wipes
- diagonal clipping
- section transitions
- product reveals

Style:
- precise
- geometric
- engineering-inspired

Avoid cheesy circular wipes everywhere.

============================================================
14. PARALLAX DEPTH
============================================================

Create 3–5 depth layers where appropriate:
1. background
2. grid/technical layer
3. product
4. foreground UI
5. text

Each layer moves at a different but subtle rate.

Do not exaggerate parallax.

============================================================
15. TECHNICAL / ROBOTICS VISUAL EFFECTS
============================================================

Useful effects:
- sensor scanning
- LiDAR point clouds
- technical grid
- trajectory lines
- joint indicators
- telemetry
- data streams
- component callouts
- system diagrams
- AI neural-network visualization
- subtle particles
- holographic overlays

Use these as information design, not decoration.

Example:
Hover over camera sensor
→ sensor highlight
→ small scanning arc
→ tooltip
→ specification panel.

============================================================
16. 3D / THREE.JS
============================================================

Use Three.js only where it creates meaningful value.

Good uses:
- hero robot
- rotating robot
- exploded technical view
- sensor visualization
- particles
- environment
- interactive product model

Lighting:
- clean studio lighting
- soft key light
- subtle rim light
- controlled reflections

Do not make the entire website a 3D game.

Performance:
- compress models
- use GLTF/GLB
- optimize polygon count
- lazy-load
- use lower quality on mobile
- respect reduced-motion preference

============================================================
17. WEBGL / SHADERS
============================================================

Optional advanced layer.

Good effects:
- subtle image displacement
- liquid transition
- noise
- scanline
- holographic distortion
- depth-based glow

Use shaders only for hero/product transitions or special moments.

Do not put heavy shader effects behind every section.

============================================================
18. AMBIENT MOTION
============================================================

The light theme should feel alive without looking busy.

Use:
- extremely slow gradient movement
- subtle noise/grain
- floating technical particles
- tiny grid movement
- soft light spots

Movement should be almost imperceptible.

The user should notice the atmosphere before noticing the animation.

============================================================
19. PAGE TRANSITIONS
============================================================

Use premium transitions between major routes.

Options:
- View Transitions API where appropriate
- GSAP route transitions
- shared-element transitions

Concept:
Current page content contracts/fades
→ technical transition
→ next page expands into place.

Do not make navigation slow.

Page transitions should usually complete quickly.

============================================================
20. APPLICATIONS SECTION
============================================================

Create an interactive horizontal application gallery.

Example:
INDUSTRIAL
→ LOGISTICS
→ HEALTHCARE
→ INFRASTRUCTURE
→ HAZARDOUS ENVIRONMENTS
→ SPACE / EXTREME ENVIRONMENTS

Each panel:
- large visual
- short title
- one-sentence explanation
- technical metrics
- subtle hover interaction

Use different image compositions to create visual rhythm.

============================================================
21. DARK/LIGHT CONTRAST STORY
============================================================

Do not keep every section identical.

Recommended rhythm:

LIGHT
Hero

LIGHT
Mission

LIGHT / GRAY
Technology

DARK
Intelligence / AI

LIGHT
Mobility

LIGHT

DARK

This creates a cinematic visual cadence.

============================================================
22. MICRO-INTERACTIONS
============================================================

Include:
- button hover
- button press
- navigation underline movement
- icon rotation
- arrow movement
- card elevation
- input focus
- tooltip reveal
- loading state
- scroll progress indicator

Micro-interactions should generally be 150–400ms.

Use spring/easing rather than linear movement wherever appropriate.

============================================================
23. MOTION LANGUAGE
============================================================

Overall motion personality:
- precise
- smooth
- intelligent
- mechanical
- controlled
- cinematic

Avoid:
- cartoon bounce
- excessive elastic movement
- random floating
- constant zooming
- aggressive spinning
- excessive blur
- animation on every element

Suggested timing:
Micro interaction: 150–300ms
UI transition: 300–500ms
Content reveal: 500–900ms
Major cinematic sequence: 1–2 seconds
Ambient animation: several seconds

Use appropriate easing:
- ease-out for entrances
- ease-in-out for transitions
- spring for interactive elements
- linear only for continuous technical loops

============================================================
24. SCROLL PROGRESS
============================================================

Use a very subtle scroll progress indicator.

Possible:
- thin line at top
- small technical progress marker
- section progress indicator

For horizontal storytelling:
- show progress such as
  PERCEPTION 01
  INTELLIGENCE 02
  MOBILITY 03

This reinforces the engineering narrative.

============================================================
25. ACCESSIBILITY
============================================================

Mandatory:
- semantic HTML
- keyboard navigation
- visible focus states
- proper ARIA labels where needed
- sufficient color contrast
- alt text
- reduced-motion support
- no essential information hidden behind hover
- buttons must remain understandable without animation

prefers-reduced-motion:
- disable parallax
- disable excessive scroll animation
- reduce 3D movement
- keep essential transitions short

============================================================
26. RESPONSIVE BEHAVIOR
============================================================

Desktop:
- full cinematic experience

Tablet:
- reduce complexity
- preserve major storytelling

Mobile:
- do NOT simply shrink desktop.
- simplify horizontal sections
- convert some horizontal storytelling into vertical cards
- reduce 3D complexity
- reduce particles
- remove custom cursor
- simplify hover-only interactions
- prioritize speed and readability

============================================================
27. PERFORMANCE
============================================================

Target:
- fast first contentful experience
- smooth scrolling
- 60fps where practical
- avoid main-thread-heavy animation

Rules:
- animate transform and opacity where possible
- avoid constantly animating layout properties
- use will-change only when justified
- lazy-load heavy assets
- compress images
- optimize fonts
- avoid unnecessary DOM nodes
- use IntersectionObserver where appropriate
- clean up GSAP/Three.js event listeners
- dispose Three.js resources
- avoid memory leaks

============================================================
28. SECTION TRANSITION LANGUAGE
============================================================

Use transitions that feel engineered.

Examples:
- white → soft gray
- soft gray → dark technical panel
- technical line draws across screen
- product passes through a mask
- typography expands/contracts
- grid becomes data visualization
- image becomes 3D scene

Avoid generic:
- huge spinning circles
- random blobs
- excessive liquid morphing
- template-style gradient blobs

============================================================
29. FINAL CTA
============================================================

The final section should feel like the conclusion of a technology film.

Suggested structure:
Dark technical background
→ subtle robot silhouette
→ strong statement
→ short supporting copy
→ primary CTA

Then transition into:
- footer
- company information
- navigation
- social links

The final CTA should be visually simple and powerful.

============================================================
31. QUALITY BAR
============================================================

Before considering the website complete, verify:

[ ] The light theme has strong contrast and does not look washed out.
[ ] Accent colors are used intentionally.
[ ] The design has enough whitespace.
[ ] Typography feels premium.
[ ] The hero immediately communicates robotics/technology.
[ ] Horizontal scrolling feels purposeful.
[ ] Horizontal sections have clear start/end points.
[ ] Robot/product interaction feels natural.
[ ] Animations do not compete with content.
[ ] Scrolling remains smooth.
[ ] Mobile experience is excellent.
[ ] Reduced-motion mode works.
[ ] No essential content depends on hover.
[ ] Images/models are optimized.
[ ] Three.js resources are properly disposed.
[ ] No animation causes layout shift.
[ ] No excessive shadows or gradients.
[ ] Dark sections are used as contrast anchors.
[ ] Every major animation has a communication purpose.
[ ] The website feels like one coherent product experience rather than many animation demos.

============================================================
32. CORE DESIGN PRINCIPLE
============================================================

DO NOT TRY TO IMPRESS THE USER WITH THE NUMBER OF ANIMATIONS.

Make the visitor feel that the interface itself is intelligent.

Every major movement should answer one of these questions:

- What is Cennzo building?
- How does the robot perceive?
- How does it think?
- How does it move?
- Where can it work?
- Why is the technology valuable?
- Why should an investor/customer trust Cennzo?

The website should communicate:
PRECISION → INTELLIGENCE → AUTONOMY → SCALE.

Final target:
A premium light-theme robotics website with cinematic horizontal storytelling, interactive product movement, controlled 3D, technical visualizations, sophisticated micro-interactions, excellent contrast, strong typography and production-grade performance.

Build for quality, not animation quantity.
