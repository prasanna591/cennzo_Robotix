CENNZO ROBOTIX — PREMIUM WEBSITE BUILD SPECIFICATION
========================================================

PURPOSE
-------
Build a world-class, premium robotics company website for CENNZO ROBOTIX.

The website must NOT feel like:
- A generic AI startup template
- A SaaS dashboard
- A Webflow/Framer clone
- A collection of animated cards
- A neon cyberpunk landing page
- An AI-generated website with random robot images

The website SHOULD feel like:
- A serious deep-tech robotics company
- Cinematic and technologically sophisticated
- Minimal, confident, and expensive
- Product-led rather than template-led
- Similar in quality of presentation to premium aerospace, automotive,
  robotics, and advanced technology brands
- Visually memorable within the first 5 seconds

IMPORTANT DESIGN DECISION
-------------------------
Do NOT use or expose the current CATIA/CAD humanoid design as the primary
website visual.

Use high-quality, consistent, cinematic humanoid imagery and conceptual
visualizations instead. The website should communicate the Cennzo vision
without pretending that concept imagery is a production-ready product.

If an image is conceptual, label it appropriately where necessary.

========================================================
1. CORE CREATIVE DIRECTION
========================================================

Brand personality:
- Intelligent
- Precise
- Ambitious
- Technical
- Human-centered
- Confident
- Future-facing
- Industrial
- Premium

Visual philosophy:
"Less interface. More experience."

The robot, imagery, typography, and storytelling are the visual focus.
UI elements should support the story rather than dominate it.

Avoid:
- Excessive gradients
- Excessive glassmorphism
- Excessive rounded cards
- Huge glowing borders
- Random particle effects
- Rainbow gradients
- Excessive neon
- Generic circuit-board backgrounds
- Excessive floating blobs
- Stock-photo-looking imagery
- Too many cards
- Constant animation

Use:
- Large typography
- Dark cinematic surfaces
- Strong whitespace
- Precise spacing
- High-quality imagery
- Subtle technical details
- Controlled contrast
- Strong composition
- Deliberate motion
- Premium microinteractions

========================================================
2. DESIGN SYSTEM
========================================================

Create the design system BEFORE building individual sections.

COLOR SYSTEM
------------
Base:
- Near black
- Graphite
- Charcoal
- Deep neutral grey
- Off-white

Use ONE primary Cennzo accent color consistently.

Do not use multiple accent colors unless required for data visualization.

Accent color should appear in:
- CTAs
- active states
- technical indicators
- selected navigation states
- subtle highlights
- important data

Do not turn the entire page into the accent color.

TYPOGRAPHY
----------
Use a premium modern sans-serif.

Possible direction:
- Geist
- Inter
- Manrope
- Satoshi

Technical/data typography:
- IBM Plex Mono
- JetBrains Mono
- another restrained monospace

Typography hierarchy:
1. Massive hero headline
2. Section headline
3. Supporting headline
4. Body
5. Technical metadata
6. Micro-labels

Large headlines should have generous tracking control and strong line height.

Use typography as a major visual element.

GRID
----
Use a professional responsive grid.

Desktop:
- Large margins
- 12-column grid
- Strong alignment

Tablet:
- 8-column structure

Mobile:
- 4-column structure

Everything should align to a consistent spacing system.

========================================================
3. TECHNOLOGY STACK
========================================================

Preferred stack:
- Next.js or React
- TypeScript
- Tailwind CSS
- Framer Motion
- GSAP + ScrollTrigger only for advanced cinematic sequences
- Lenis for smooth scrolling if it does not compromise accessibility/performance
- React Three Fiber / Three.js only where genuine 3D adds value
- Optimized WebP/AVIF images
- GLB/GLTF only for optimized 3D assets

Do NOT add libraries just because they are fashionable.

Every dependency must have a clear purpose.

========================================================
4. 21ST.DEV USAGE STRATEGY
========================================================

Use 21st.dev as a source of component and interaction inspiration.

DO NOT copy an entire visual identity.

Appropriate uses:
- Navigation patterns
- Magnetic buttons
- Text reveal ideas
- Spotlight interactions
- Hover states
- Cursor interactions
- Animated UI details
- Modern component patterns
- Microinteractions

The final implementation must look like Cennzo, not like 21st.dev.

Before implementing a component, ask:
"Does this improve the Cennzo story?"

If not, remove it.

========================================================
5. UI/UX PRO MAX USAGE STRATEGY
========================================================

Use UI/UX Pro Max to establish:
- Design system
- Typography

- UX consistency
- Accessibility
- Responsive behavior
- Component structure
- Spacing
- Interaction rules

Do NOT blindly follow generated recommendations.

The final creative direction takes priority.

========================================================
6. FRAMER MOTION STRATEGY
========================================================

Framer Motion is a CORE part of the experience.

Create a consistent motion language.

MOTION PRINCIPLES
-----------------
Motion should feel:
- Controlled
- Physical
- Mechanical
- Smooth
- Deliberate
- Expensive

Avoid:
- Bouncy UI everywhere
- Excessive spring effects
- Random floating
- Continuous movement
- Animating every element

TEXT ANIMATION
--------------
Use:
- opacity
- y translation
- clip/mask reveals
- staggered words or lines

Example:
Headline begins below an invisible mask and rises into position.

IMAGE ANIMATION
---------------
Use subtle:
- scale
- opacity
- parallax
- position shifts

Typical cinematic pattern:
scale 1.05 -> 1.00

BUTTONS
-------
Use subtle:
- scale
- background transition
- icon movement

Do not make buttons bounce.

SCROLL ANIMATION
----------------
Use scroll-linked animation strategically.

Only major moments should have major movement.

========================================================
7. MOTION SYSTEM
========================================================

Define reusable animation constants.

Example conceptual system:

FAST:
~180–250ms

STANDARD:
~400–600ms

CINEMATIC:
~800–1400ms

Use appropriate easing.

Prefer:
- easeOut
- custom cubic-bezier
- carefully controlled spring

Do not use arbitrary durations everywhere.

Create reusable animation variants.

Examples:
- fadeUp
- fadeIn
- revealText
- imageReveal
- scaleReveal
- staggerChildren
- sectionReveal
- hoverLift
- magneticButton

========================================================
9. HERO SECTION
========================================================

The hero is the most important section.

Goal:
Create a "wow" moment within 5 seconds.

Visual:
- Premium cinematic humanoid imagery
- Dark environment
- Strong directional lighting
- High contrast
- Subtle atmospheric depth
- Minimal interface

Headline direction:

PHYSICAL
INTELLIGENCE.

or

INTELLIGENCE
IN MOTION.

Supporting copy:
Cennzo Robotix develops intelligent robotic systems designed to perceive,
reason, and act in the physical world.

CTA:
EXPLORE THE SYSTEM

Secondary CTA:
OUR VISION

Do not overload the hero with information.

HERO ANIMATION
-------------
Page loads:
1. Black/near-black background
2. Very subtle atmosphere appears
3. Robot image fades/reveals
4. Headline enters using masked text reveal
5. Supporting copy appears
6. Navigation settles
7. CTA becomes interactive

Do NOT delay the page excessively just for animation.

Respect prefers-reduced-motion.

22. MICROINTERACTIONS
========================================================

Add only high-value microinteractions.

Examples:
- Magnetic CTA

- Image zoom on hover

- Navigation underline transitions
- Cursor spotlight in selected sections
- Number counters when entering viewport
- Horizontal line drawing
- Image masking transitions

Do not animate everything.

========================================================
25. IMAGE PERFORMANCE
========================================================

Images must be optimized.

Use:
- AVIF where supported
- WebP fallback
- responsive srcsets
- lazy loading below the fold
- priority loading only for hero assets

Do not ship giant uncompressed images.

========================================================
26. 3D USAGE
========================================================

3D is optional.

Do NOT use 3D simply because the website is a robotics website.

Use 3D if it creates genuine value.

Potential uses:
- Abstract robotic system
- Conceptual humanoid
- Interactive environment
- Data visualization

Avoid loading a huge CAD model.

Target fast loading.

Provide fallback imagery for low-performance devices.

========================================================
27. RESPONSIVE DESIGN
========================================================

Mobile is NOT an afterthought.

The experience must be designed for:

- Desktop
- Tablet
- Mobile

On mobile:
- Simplify cinematic sequences
- Reduce particle effects
- Reduce parallax
- Disable expensive cursor effects
- Optimize images
- Maintain typography hierarchy
- Preserve the story

No horizontal overflow.

No broken animations.

No tiny text.

Touch targets must be accessible.

========================================================
28. ACCESSIBILITY
========================================================

Implement:
- Semantic HTML
- Proper headings
- Keyboard navigation
- Visible focus states
- Accessible buttons
- Alt text
- Reduced-motion support
- Good contrast
- Screen-reader-friendly navigation

Use prefers-reduced-motion.

When reduced motion is enabled:
- Replace complex scroll animation with simple fades
- Remove cursor effects
- Remove unnecessary parallax
- Keep content fully accessible

========================================================
29. PERFORMANCE
========================================================

Target:
- Fast initial load
- Excellent Core Web Vitals
- Minimal JS where possible
- Lazy-loaded sections
- Optimized fonts
- Optimized images
- GPU-conscious animation

Avoid:
- Massive video backgrounds
- Huge GLB files
- Unnecessary canvas animations
- Infinite particle systems
- Excessive DOM nodes

Animations should preferably use:
transform
opacity

Avoid animating expensive layout properties continuously.

========================================================
33. OPEN CODE WORKING METHOD
========================================================

Do not continuously regenerate entire files.

Before modifying a file:
1. Read the existing file.
2. Understand its architecture.
3. Make the smallest appropriate change.
4. Run the project.
5. Check for errors.
6. Continue.

After each major section:
- Build
- Test
- Fix
- Review visually

Do not introduce unnecessary dependencies.

34. QUALITY CONTROL CHECKLIST
========================================================

Before considering the website complete, ask:

BRAND
-----
[ ] Does it immediately feel like Cennzo?
[ ] Does it feel like a robotics company?
[ ] Does it feel premium?
[ ] Is the visual language consistent?

VISUAL
------
[ ] Are images high quality?
[ ] Is the robot identity consistent?
[ ] Is there enough whitespace?
[ ] Is typography strong?
[ ] Are sections visually varied?

MOTION
------
[ ] Does motion have a purpose?
[ ] Are transitions smooth?
[ ] Is there a consistent motion language?
[ ] Are there no annoying loops?
[ ] Is reduced motion supported?

UX
--
[ ] Can users understand Cennzo within 10 seconds?
[ ] Can users understand what the company builds?
[ ] Are CTAs clear?
[ ] Is navigation intuitive?
[ ] Does mobile work perfectly?

TECHNICAL
---------
[ ] No console errors
[ ] No broken links
[ ] No layout overflow
[ ] Images optimized
[ ] Animations performant
[ ] SEO configured
[ ] Accessibility checked

PREMIUM TEST
------------
Ask:

"If I remove all animations, does the website still look premium?"

If NO:
Fix the visual design.

Then ask:

"If I remove the images, does the typography/layout still feel intentional?"

If NO:
Fix the composition.

Then ask:

"If I remove the text, does the visual experience still communicate robotics?"

If NO:
Fix the art direction.
